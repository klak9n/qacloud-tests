## BUG-001 — POST и PUT /api/groceries принимают отрицательное значение price

| Параметр | Значение |
|---|---|
| ID | BUG-001 |
| Severity | Major |
| Priority | High |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | PROD-018, PROD-025 |

### Шаги воспроизведения

**Создание товара:**
1. Отправить `POST /api/groceries` с телом:
   ```json
   { "name": "Test Product", "price": -10, "category": "Dairy" }
   ```

**Обновление товара:**
2. Отправить `PUT /api/groceries/:id` (id — валидный существующий товар) с телом:
   ```json
   { "price": -24 }
   ```

### Ожидаемый результат
`400 Bad Request` в обоих случаях — цена товара не может быть отрицательной.

### Фактический результат
- POST: `201 Created`, товар создаётся с `price: -10`
- PUT: `200 OK`, цена товара обновляется на `-24`

Подтверждено повторным `GET /api/groceries/:id` — отрицательное значение сохраняется в БД, а не является отображаемой ошибкой.

## BUG-002 — Несогласованная валидация price = 0 между POST (400) и PUT (200)

| Параметр | Значение |
|---|---|
| ID | BUG-002 |
| Severity | Major |
| Priority | Medium |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | PROD-017, PROD-024 |

### Шаги воспроизведения

**Создание товара:**
1. Отправить `POST /api/groceries` с телом:
   ```json
   { "name": "Test Product", "price": 0, "category": "Dairy" }
   ```

**Обновление товара:**
2. Отправить `PUT /api/groceries/:id` (id — валидный существующий товар) с телом:
   ```json
   { "price": 0 }
   ```

### Ожидаемый результат
Одинаковое поведение на обоих эндпоинтах: оба возвращают `400 Bad Request`.

### Фактический результат
- POST: `400 Bad Request`
- PUT: `200 OK`, цена товара обновляется на `0`

Один и тот же бизнес-инвариант ("цена не может быть нулевой") соблюдается при создании и не соблюдается при обновлении.

## BUG-003 — Сообщение об ошибке при price = 0 не соответствует причине ошибки

| Параметр | Значение |
|---|---|
| ID | BUG-003 |
| Severity | Minor |
| Priority | Low |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | PROD-017 |

### Шаги воспроизведения
1. Отправить `POST /api/groceries` с телом:
   ```json
   { "name": "Test Product", "price": 0, "category": "Dairy" }
   ```

### Ожидаемый результат
`400 Bad Request` с сообщением, корректно описывающим причину ошибки, а именно недопустимое значение `price`.

### Фактический результат
`400 Bad Request`, но текст ошибки:
```json
{ "error": "product_name/name, price, and category are required" }
```
Сообщение сформулировано так, будто поле `price` отсутствует в запросе, хотя оно присутствует.

## BUG-004 — Категория Meat, заявленная в документации, отсутствует в дефолтном каталоге

| Параметр | Значение |
|---|---|
| ID | BUG-004 |
| Severity | Major |
| Priority | Medium |
| Окружение | qacloud.dev Market API, Postman + Wiki документация |
| Связанные тест-кейсы | PROD-005, PROD-006 |

### Шаги воспроизведения
1. Выполнить POST /api/reset.
2. Выполнить GET /api/groceries и проверить категории.
3. Отправить GET /api/groceries/filter?category=Meat
4. Отправить GET /api/groceries/filter?category=meat-seafood

### Ожидаемый результат
Запрос по категории `Meat`, заявленной в документации как часть дефолтного набора сид-данных, должен возвращать соответствующие товары.

### Фактический результат
- `category=Meat` → `200 OK`, `[]` (пустой список)
- `category=meat-seafood` → `200 OK`, список с товарами этой категории
