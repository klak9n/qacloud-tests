## BUG-P01 — POST и PUT /api/groceries принимают отрицательное значение price

| Параметр | Значение |
|---|---|
| ID | BUG-P01 |
| Severity | Major |
| Priority | High |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | PROD-018, PROD-025 |

### Шаги воспроизведения

**Создание товара:**
1. Отправить `POST /api/groceries` с телом:
   ```json
   { "name": "Test Product", "price": -10, "category": "Dairy" }
   ```

**Обновление товара:**
2. Отправить `PUT /api/groceries/:id` (id — валидный существующий товар) с телом:
   ```json
   { "price": -24 }
   ```

### Ожидаемый результат
`400 Bad Request` в обоих случаях — цена товара не может быть отрицательной.

### Фактический результат
- POST: `201 Created`, товар создаётся с `price: -10`
- PUT: `200 OK`, цена товара обновляется на `-24`

Подтверждено повторным `GET /api/groceries/:id` — отрицательное значение сохраняется в БД, а не является отображаемой ошибкой.

## BUG-P02 — Несогласованная валидация price = 0 между POST (400) и PUT (200)

| Параметр | Значение |
|---|---|
| ID | BUG-P02 |
| Severity | Major |
| Priority | Medium |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | PROD-017, PROD-024 |

### Шаги воспроизведения

**Создание товара:**
1. Отправить `POST /api/groceries` с телом:
   ```json
   { "name": "Test Product", "price": 0, "category": "Dairy" }
   ```

**Обновление товара:**
2. Отправить `PUT /api/groceries/:id` (id — валидный существующий товар) с телом:

## BUG-B01 — quantity = 0 возвращает сообщение "required" вместо "must be at least 1"

| Параметр | Значение |
|---|---|
| ID | BUG-B01 |
| Severity | Minor |
| Priority | Low |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | BASK-004 |

### Шаги воспроизведения

**Добавление товара в корзину:**
1. Отправить `POST /api/basket` с телом:
   ```json
   { "product_id": "<валидный id>", "quantity": 0 }
   ```

**Обновление количества в корзине:**
2. Отправить `PUT /api/basket/:id` (id — валидная существующая позиция корзины) с телом:
   ```json
   { "quantity": 0 }
   ```

### Ожидаемый результат
`400 Bad Request` с сообщением `"quantity must be at least 1"` в обоих случаях — по аналогии с поведением при отрицательном `quantity` (`-1`, `-2`), где именно это сообщение и возвращается.

### Фактический результат
`400 Bad Request` в обоих случаях, но текст ошибки:
```json
{ "error": "product_id and quantity are required" }
```
Сообщение сформулировано так, будто поле `quantity` отсутствует в запросе, хотя оно присутствует и равно `0`. При этом `quantity: -1`/`-2` в тех же условиях корректно возвращает `"quantity must be at least 1"`.

## BUG-B02 — Невалидный тип quantity/id вызывает 500 с сырой ошибкой БД вместо 400

| Параметр | Значение |
|---|---|
| ID | BUG-B02 |
| Severity | Major |
| Priority | High |
| Окружение | qacloud.dev Market API, Postman |
| Связанные тест-кейсы | BASK-005, BASK-008, BASK-010 |

### Шаги воспроизведения

**Добавление товара с нечисловым quantity:**
1. Отправить `POST /api/basket` с телом:
   ```json
   { "product_id": "<валидный id>", "quantity": "asf" }
   ```

**Обновление количества нечисловым значением:**
2. Отправить `PUT /api/basket/:id` (id — валидная существующая позиция корзины) с телом:
   ```json
   { "quantity": "asd" }
   ```

**Удаление по невалидному формату id:**
3. Отправить `DELETE /api/basket/{166}` (значение не соответствует формату UUID)

### Ожидаемый результат
`400 Bad Request` во всех трёх случаях с понятным сообщением о некорректном формате входных данных (например, `"quantity must be a number"` или `"invalid id format"`).

### Фактический результат
Во всех трёх случаях — `500 Internal Server Error` с сырым текстом ошибки базы данных:
```json
{ "error": "invalid input syntax for type integer: \"asf\"" }
```
```json
{ "error": "invalid input syntax for type uuid: \"{166}\"" }
```
Входные данные не проходят валидацию на уровне приложения и попадают напрямую в SQL-слой, где вызывают необработанное исключение.

## BUG-UI-01 — Документация описывает единый счётчик "Basket Items", в UI — два разных элемента

| Параметр | Значение |
|---|---|
| ID | BUG-UI-01 |
| Severity | Minor |
| Priority | Low |
| Окружение | qacloud.dev Market, Chrome |
| Связанные тест-кейсы | UI-001 |

### Шаги воспроизведения
1. Зафиксировать значения счётчика в шапке (иконка Basket) и стата "Basket Units" на дашборде — оба равны 0.
2. Добавить в корзину 1 товар с `quantity: 3`.
3. Сравнить итоговые значения обоих элементов с описанием `TC-UI-001` в Wiki.

### Ожидаемый результат
Согласно Wiki (`TC-UI-001`), единый счётчик "Basket Items" должен увеличиться на 3 (на величину добавленного количества).

### Фактический результат
В интерфейсе нет элемента с названием "Basket Items". Есть два разных элемента с разной логикой подсчёта:
- значок корзины в шапке — увеличивается на **1** (считает количество уникальных товарных позиций);
- стат "Basket Units" на дашборде — увеличивается на **3** (считает суммарное количество единиц товара).

## BUG-UI-02 — Кнопка Reset документирована в верхней навигации, реально находится в Data Viewer

| Параметр | Значение |
|---|---|
| ID | BUG-UI-02 |
| Severity | Minor |
| Priority | Low |
| Окружение | qacloud.dev Market, Chrome |
| Связанные тест-кейсы | UI-004 |

### Шаги воспроизведения
1. Удалить любой товар через UI.
2. Попытаться найти кнопку "Reset" в верхней навигационной панели (согласно `TC-UI-007`).
3. Открыть раздел "Data Viewer" из той же навигационной панели.

### Ожидаемый результат
Кнопка "Reset" присутствует непосредственно в верхней навигационной панели, рядом с другими элементами навигации (Wiki, API Docs и т.д.).

### Фактический результат
В верхней навигации кнопки "Reset" нет. Функция сброса данных находится внутри раздела "Data Viewer" и доступна только после перехода в него.

Сама функциональность сброса при этом работает корректно: после её вызова удалённый товар восстанавливается, счётчик Products возвращается к исходному значению.

## BUG-UI-04 — Создание товара с price = 0 молча проваливается без сообщения об ошибке

| Параметр | Значение |
|---|---|
| ID | BUG-UI-04 |
| Severity | Major (UX) |
| Priority | Medium |
| Окружение | qacloud.dev Market, Chrome |
| Связанные тест-кейсы | UI-007 |

### Шаги воспроизведения
1. Открыть форму "Add a Product".
2. Заполнить все обязательные поля валидными значениями, кроме `Price`, куда ввести `0`.
3. Нажать кнопку создания товара.

### Ожидаемый результат
Либо товар создаётся (если 0 — допустимое значение), либо форма отображает понятное сообщение об ошибке, аналогично тому, как это сделано для отрицательных значений (`"пожалуйста, выберите значение не менее 0"`) или для некорректного типа данных (`"пожалуйста введите число"`).

### Фактический результат
Товар не создаётся, но никакого сообщения об ошибке или иной обратной связи не появляется. Пользователь не может понять, почему действие не выполнилось.
